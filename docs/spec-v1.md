# 小米 15 微信记账 Agent V1 规格

## Problem Statement

用户希望在自己的小米 15 上追踪微信新交易，减少手动记账，同时保留核对、补录和修改能力。普通 Android App 无法无条件取得微信完整流水，必须先验证实际可采集字段。

## Solution

独立实现本地优先 Android App。通知和可选无障碍采集微信支付线索，必要时本地 OCR 兜底；金额、方向和状态明确才自动入账，存疑进入待确认。完整账本建立后接入 DeepSeek 按需分类、自然语言记账和账本问答。

## User Stories

1. 作为个人用户，我希望安装 APK 到小米 15，以验证微信采集能力。
2. 作为用户，我希望逐项开启通知和无障碍权限，以控制数据来源。
3. 作为用户，我希望查看权限状态和采集结果，以知道哪些路径正在工作。
4. 作为用户，我希望只采集微信支付相关内容，以避免记录普通聊天。
5. 作为用户，我希望付款、退款、转账、收款和红包完成状态被区分，以避免把待支付事件计入收支。
6. 作为用户，我希望缺失金额保留为空，以避免出现猜测的金额或零元账单。
7. 作为用户，我希望文字不可读时尝试本地 OCR，以增加可识别的支付页面。
8. 作为用户，我希望截图识别后释放且不上传，以保护支付信息。
9. 作为用户，我希望诊断记录可清除，并且不自动云备份。
10. 作为用户，我希望采集候选在核对前不进入统计。
11. 作为用户，我希望手动新增、编辑和删除账单，以补充无法自动采集的交易。
12. 作为用户，我希望已知商户自动分类，未知商户可按需 AI 分类并记住规则。
13. 作为用户，我希望真实的连续同金额交易都保留，同时相同事件不重复入账。
14. 作为用户，我希望浏览历史详情不触发新账单。
15. 作为用户，我希望内部转账排除统计，退款抵扣消费而不计普通收入。
16. 作为用户，我希望在手机中配置并安全保存 DeepSeek 密钥，不把密钥写进 APK。
17. 作为用户，我希望输入自然语言后核对账单预览，确认后再保存。
18. 作为用户，我希望通过聊天查询真实账本，汇总金额由数据库而不是模型计算。
19. 作为用户，我希望聊天修改或删除先展示建议，确认后才改变账本。
20. 作为用户，我希望断网或模型失败时仍能本地记账。
21. 作为用户，我希望月度收支、退款、分类构成清晰呈现。
22. 作为用户，我希望暖色、有质感的界面，同时保证文字和权限状态清晰可读。
23. 作为用户，我希望重启、锁屏和后台运行经过实测，并明确未支持场景。
24. 作为用户，我希望 App 更新保留账本数据。

## Implementation Decisions

- Kotlin、Compose、Material 3；Android 12+。完整账本阶段采用 Room，金额为人民币整数分。
- 首阶段为采集诊断 App：本地候选列表、权限引导、可选 OCR、错误诊断、清除记录、手工记录实测场景结果；不包含正式账本或云端调用。
- 只有微信包名下与支付相关的事件进入解析。无障碍仅读取用户已打开的可见页面，不自动点击、付款或遍历历史账单。
- 候选包含采集时间、来源、可用金额与方向、状态、可选交易号及诊断原因。缺失字段保留为空。
- 待处理或冲突交易不得标记可入账。采集验证阶段所有结果仅为候选，无正式记账副作用。
- 先以可靠交易号和事件标识去重；没有可靠标识时不按金额删除交易。跨来源疑似重复在完整账本阶段交给用户核对。
- 本地 OCR 仅在明确的实时支付相关页面触发，截图不落盘、不上传，识别后释放。无法判断页面用途时不截图。
- 本地诊断最多保留最近 100 条，普通聊天不保存；默认不自动云备份。用户可清空。
- 界面为暖白、沙色、琥珀色，深棕文字，使用系统中文字体、足够触摸面积与明确状态标签。
- 完整 App 包含账本、统计、Agent、设置。分类本地优先；DeepSeek 请求只包含当次必要文本或汇总，不发送整个账本或截图。
- 模型返回限定的查询和修改建议，程序负责校验；不执行模型 SQL。所有聊天写操作经用户确认。
- 个人转账与红包默认收支，可修改为内部转账；退款抵扣消费。

## Testing Decisions

确认过的公开边界为：采集文本→候选；确认入账→列表与统计；聊天指令→查询或待确认修改。
逐次执行失败测试→最小实现→通过，测试来自独立样例，不重复计算实现逻辑。
新仓库没有可复用的应用测试。采集阶段测试普通聊天过滤、完成与待处理状态、金额缺失与冲突、来源过滤、可靠事件去重、历史详情拒绝和本地诊断容量。
后续增加退款、内部转账、连续同金额真实交易，以及模型失败与取消修改等测试。
真机记录 HyperOS、Android、微信版本以及每条路径的结果；无法运行真机时不得声明兼容或关闭采集任务。

## Out of Scope

支付宝、历史账单导入、Root/Hook、后端、云同步、多账本、多币种、语音记账、微信付款自动操作。

## Further Notes

依赖顺序：采集验证 APK → 本地账本 → 自动入账 → Agent → 安装验收。
首阶段需在小米 15 上确认采集事实，才继续完整账本实现。通知或页面不可读时提供补录入口，不承诺全部流水覆盖。

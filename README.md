# 微信记账 Agent

一款面向个人使用的 Android 记账 App，计划通过手机上的微信支付通知和支付页面识别新交易，自动记录收支，同时保留手动记账、自然语言记账和账本问答。

首个适配设备为 **小米 15**，最低支持 **Android 12**。

> 当前状态：第一版计划已确认，尚未开始功能开发。仓库目前提供项目说明，没有可安装的 APK；下文功能均为计划内容，未经过真机验证。

## 第一版功能

| 功能 | 计划行为 |
| --- | --- |
| 微信自动记账 | 采集安装后的消费、退款、个人转账、收款和红包交易 |
| 手动记账 | 新增、编辑、删除账单，调整分类和交易类型 |
| 待确认账单 | 保存字段缺失、识别冲突或疑似重复的候选记录，确认前不计入统计 |
| 自动分类 | 优先使用本地商户规则；未知商户归入“其他”，可按需使用 AI 分类并记住规则 |
| 收支统计 | 展示月度收支、退款和分类构成，支持将内部转账排除在收支之外 |
| 自然语言记账 | 将“午饭花了 35 元”等输入转换为可编辑的账单预览，确认后保存 |
| 账本问答 | 按日期、分类、商户和收支方向查询，由本地数据库计算真实结果，AI 负责理解与解释 |

界面规划为四个页面：**账本、统计、Agent、设置**。

## 微信采集与入账规则

1. **通知监听**：只处理微信包名下与支付相关的通知。
2. **可选无障碍识别**：读取微信支付相关页面的可见文字。
3. **本地 OCR 兜底**：明确识别到支付相关页面且无法读取文字时，尝试截图并在手机本地识别；截图不上传，解析后释放。

只有明确完成的交易才能自动入账。“待支付”“请收款”“红包待领取”等状态不计入收支。金额、方向或交易状态不明确时，记录进入待确认；缺失金额不得记成零元，也不得由 AI 猜测。

去重优先使用微信交易号和采集事件标识。缺少可靠标识的跨渠道疑似重复记录交给用户确认，不能仅凭同金额删除记录。浏览历史详情不应触发新的自动入账。

个人转账和红包默认按实际流入、流出计收支；用户可改为内部转账并排除统计。退款单独记录、抵扣消费，不作为普通收入。

### 采集边界

这款 App 不直接读取微信的完整交易数据库，也不承诺同步全部微信流水。通知是否产生、是否包含金额、页面是否可读、系统是否允许截图，以及后台服务是否存活，都会影响采集结果。

无法取得可靠数据时，将展示采集限制并提供待确认或手动补录入口。付款、转账、收款、红包和退款的具体覆盖情况，以小米 15 的实测记录为准。

## AI 与隐私

- 账本保存在手机本地，第一版不建立后端或云同步。
- 首个模型服务为 **DeepSeek**，由 App 直接调用；用户在手机设置中填写 API 密钥，使用 Android Keystore 保护，不写入源码或 APK。
- 普通交易解析和已有商户分类优先在本地完成，云端 AI 按需调用。
- 云端只接收当前请求必要的文本或汇总结果，不发送整个账本、无关聊天或支付截图。
- 聊天新增、修改、删除账单均先展示结果，用户确认后才执行。
- 模型只能提出限定的结构化查询或修改建议，不能直接执行 SQL、修改数据库或操作微信付款。
- 断网、未配置密钥或模型请求失败时，本地采集和手动记账仍应可用。

## 技术方案

| 部分 | 方案 |
| --- | --- |
| 开发语言 | Kotlin |
| 界面 | Jetpack Compose + Material 3 |
| 本地数据 | Room |
| 金额 | 人民币整数分，避免浮点金额误差 |
| 通知采集 | NotificationListenerService |
| 页面识别 | 可选 AccessibilityService + 本地 OCR |
| 云端模型 | DeepSeek API |
| 密钥保护 | Android Keystore |

实施前配置 JDK 17 和 Android SDK。构建命令、安装包下载入口和权限配置说明将在对应任务完成并验证后补充。

## 开发流程与里程碑

采用 **需求澄清 → 规格说明 → 任务拆分 → TDD 实现 → 安装验收** 的流程，对应 skills 为 `grill-with-docs → to-spec → to-tickets → tdd`；换会话时使用 `handoff`。

规格、验收标准和开发任务保存在本仓库的 [GitHub Issues](https://github.com/Xixi051108/accountingApp/issues)。项目规则、术语表和必要的架构决策文档将在实施时建立。

| 顺序 | 任务 | 交付与前置条件 |
| --- | --- | --- |
| 1 | 采集验证 APK | 在小米 15 验证通知、页面文字、OCR 和后台运行，记录各交易类型可取得的字段 |
| 2 | 本地账本 | 在采集验证完成后，实现手动记账、编辑删除、待确认和基础统计 |
| 3 | 自动入账 | 接入已验证的采集路径，完成状态判断、分类和去重 |
| 4 | Agent | 接入 DeepSeek，实现确认后记账和基于真实账本的问答 |
| 5 | 安装验收 | 生成个人使用 APK，验证更新后数据保留，提供权限配置说明 |

**先验证采集能力，再推进完整账本开发。** 未验证的交易类型不能标记为自动采集成功。

## 验证计划

TDD 聚焦三个行为边界：

- **采集文本 → 候选账单**：验证金额、方向、完成状态；无金额、普通聊天、未领取红包和历史详情不得误入账。
- **确认入账 → 列表与统计**：验证退款、内部转账、编辑删除、重复事件，以及连续两笔真实同金额交易。
- **聊天指令 → 查询或待确认修改**：验证统计与数据库一致；取消确认、非法模型输出和网络失败不得改变账本。

真机验收覆盖通知权限、无障碍、OCR、锁屏、重启和后台运行，并记录实际 HyperOS、Android、微信版本及各场景结果。完成相应任务后运行测试、构建 APK 并检查最终 diff。

## 第一版范围
